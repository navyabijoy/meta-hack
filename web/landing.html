How it works

From screen recording to failing test to verified fix.

The run

Attach a recording to an issue. Gecko does the rest, and checks every claim by running code.

  1. 01Watch the recording

    Frames are sampled where the screen changes and tiled into contact sheets. Narration is transcribed. Muse Spark writes the steps, what should have happened, and the frame that shows the bug.

    Muse Voice Transcribe · Muse Spark
  2. 02Find what was clicked

    SAM finds the cursor and every look-alike element on screen, so Gecko knows it was "the 2nd × of 2", then finds the same one in the live page. No pixel mapping.

    SAM 3.1
  3. 03Reproduce it as a test

    A Playwright replay runs the steps in Chrome. The test must fail on an assertion and the screen must match the video. If not, Gecko tries how the user's actions might have differed, like a double click.

    Playwright · Muse Spark
  4. 04Fix it, with proof

    Muse Code patches the app against that failing test. The patch counts only if the test passes, the test is untouched, and the suite stays green. Up to 3 rounds.

    Muse Code · GitHub

    Built for production

    Verification, not trust.

    A run reports reproduced only when the test fails on an assertion and the replay's screen matches the video's bug frame.A fix is accepted only when the new test passes, the test file is byte-identical, and the existing suite is green.
    If Gecko can't reproduce a bug, it says so on the issue, with its evidence. It never opens a speculative PR.In the eval, a user reported a task vanishing on reload. The video showed it didn't. Gecko declined after 3 attempts.
    Every run clones your repo into its own folder and starts the app on a free port. Your checkout is never touched.Lockfile-keyed install cache, a durable SQLite queue, and crashed runs re-queued once on restart.
    A global cap and a per-run cap, with every model call attributed to its run in a ledger.Per-run cap defaults to $3. Calls retry 429s and 5xx with jittered backoff and honour Retry-After.
    The GitHub App asks only for contents, issues and pull requests, with short-lived tokens.Muse Code runs with its OS sandbox on and web tools off. Contributor mode is off, so your code is not used for training.
    Setup

    Three steps to your repo.

    1. Add Gecko to GitHubPick the repositories Gecko should watch. Sign in with the same GitHub account to see your workspace.
    2. Add a .gecko.ymlTell Gecko how to install, start and test your app. Playwright reads its base URL from GECKO_BASE_URL.
    3. Share your report linkSupport, QA or customers send a recording through it, no GitHub account needed. Gecko files the issue and opens the fix. You can also attach a video to any issue, or comment /gecko on an older one.
